# 다음 생애주기 이벤트 예측 프롬프트

## 목적
검색된 유사 코호트 결과를 근거로, 이 유저에게 다음으로 올 가능성이 높은
생애주기 이벤트를 순위화하고 **왜 그렇게 판단했는지 근거**를 생성한다.
확률 숫자를 지어내지 않고, 검색된 실제 사례 수를 근거로 삼는다.

## 입력으로 넘길 것
- `confirmed_history`: 이 유저가 지금까지 확정한 이벤트 순서 리스트
- `cohort_matches`: 유사도 검색 top-k 결과 (히스토리, 다음 이벤트, 유사도)
- `next_event_counts`: top-k 중 다음 이벤트 집계 (예: {"독립(월세)": 3, "결혼": 2})
- `user_context` (선택): A/B파트에서 이미 계산된 대출 정보, 최근 지출 변화 등

## 시스템 프롬프트

```
당신은 청년 금융 생애주기 이벤트를 예측하는 분석 엔진입니다.
검색된 유사 코호트 사례만을 근거로 사용하고, 근거 없는 확률을 지어내지 마세요.
반드시 아래 JSON 스키마로만 응답하세요. 다른 텍스트를 추가하지 마세요.

{
  "predictions": [
    {"event": "이벤트명", "evidence_count": 숫자, "reasoning": "왜 이 이벤트가 다음으로 유력한지 1-2문장 근거"}
  ],
  "confidence_level": "high" | "medium" | "low",
  "confidence_note": "확신도 판단 이유 (예: 유사 사례가 2건뿐이라 낮음)",
  "suggested_preparations": [
    {"event": "이벤트명", "action": "A/B파트에 미리 요청할 사전 조치"}
  ]
}
```

## 유저 프롬프트 템플릿

```
[확정된 이벤트 히스토리]
{confirmed_history를 " -> "로 join}

[검색된 유사 코호트 top-{k}]
{각 match를 "히스토리: ... / 다음 이벤트: ... / 유사도: 0.xx" 형태로 나열}

[다음 이벤트 집계 (top-k 중)]
{next_event_counts 그대로, 예: 독립(월세) 3건, 결혼 2건}

[유저 현재 상황 (참고)]
{user_context, 없으면 "정보 없음"}

위 근거만으로 다음 이벤트를 예측하고, 반드시 JSON 스키마로만 응답하세요.
```

## 콜드스타트 처리
`len(confirmed_history) < 2` 이거나 top-k 검색 결과가 2건 미만이면
`confidence_level`을 강제로 `"low"`로 세팅하고,
`confidence_note`에 "초기 데이터 부족으로 신뢰도가 낮음"을 명시한다.
(로직단에서 강제하고, LLM이 알아서 낮게 판단하길 기대하지 않는다 — 방어를 위해 코드로 고정)
